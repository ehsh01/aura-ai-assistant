# Recall AI App — Vision & Product Philosophy

## 1. North Star

Recall is an AI-powered personal operating system designed to help Ernesto manage work, life, projects, information, and follow-ups without being overwhelmed by scattered inputs.

Recall is not intended to become just another task manager, note-taking tool, ticketing tool, finance app, or document storage system. It is an intelligence layer that connects information from many places, turns it into structured knowledge, and helps the user decide what deserves attention next.

The guiding mission is:

> Capture once. Organize automatically. Act with confidence. Verify everything.

## 2. Why Recall Exists

The user receives information from many disconnected channels:

- Ticketing system emails
- Outlook email
- Microsoft Teams messages
- Text messages
- Browser pages
- Notes
- Construction/home expense records
- Personal finance data
- Documents
- Spreadsheets
- Vendor communications
- Work follow-ups
- Family and household information

The problem is not that the user lacks tools. The problem is that each tool holds only part of the truth.

Recall exists to reduce mental load by making scattered information actionable, searchable, connected, and verifiable.

## 3. What Recall Should Become

Recall should evolve into a personal command center with sections such as:

- Today
- Inbox
- Tasks
- People
- Projects
- Tickets
- Finance
- Home / Construction
- Knowledge
- Documents
- Family
- Connectors
- Evidence

These should not be isolated applications. They should be different views of the same connected knowledge system.

A captured Teams message can become:

- a task
- a person interaction
- a project update
- an evidence source
- a reminder
- a searchable knowledge item

The user should never have to duplicate the same information manually across modules.

## 4. Core Product Principles

### 4.1 Capture Must Be Fast

The user’s work is interrupt-driven. Recall must respect that reality.

Capture should usually take one or two actions:

- paste text
- click browser extension
- upload file
- import spreadsheet
- call connector sync
- send data through API

The capture flow must never feel like data entry.

### 4.2 Recall Must Be Trustworthy

The app must not become an AI black box.

Every important summary, recommendation, financial total, task, due date, or answer must be connected to evidence.

If Recall says:

> You spent $8,573 on drywall.

The user should be able to click the number and see the exact transactions behind it.

If Recall says:

> Dr. Smith asked you to follow up today.

The user should be able to see the original email, Teams message, ticket, or note that supports the statement.

### 4.3 Source Systems Remain Sources of Truth

Recall should not unnecessarily replace mature systems.

Examples:

- The finance app remains the source of truth for bank and transaction data.
- The ticketing system remains the official source of tickets.
- Email remains the source of communication history.
- Construction tools or exported spreadsheets remain the source of original project expenses.

Recall indexes, connects, summarizes, and reasons across them.

### 4.4 One App, Modular Architecture

Recall should be one app with many modules, not many disconnected apps.

A unified architecture will allow features to compound over time. New modules should reuse the same capture, evidence, connector, AI, and query systems.

### 4.5 Human Correction Is Essential

AI extraction will never be perfect. The UI must always allow the user to correct:

- task title
- requester
- due date
- priority
- project
- source mapping
- category
- financial classification
- evidence association

Corrections should improve future AI behavior when possible.

## 5. What Recall Is Not

Recall is not:

- a replacement for every system
- a generic notes app
- a Trello clone
- a standalone ticketing system
- a finance ledger
- a black-box AI assistant
- a document dump
- a chat-only interface
- a tool that requires perfect formatting

Recall should avoid becoming bloated by trying to own data that belongs somewhere else.

## 6. Product Success Definition

Recall is successful when:

- Ernesto captures information faster than before.
- Important work does not get lost across email, Teams, tickets, and notes.
- AI-generated answers can be verified.
- Tasks, people, projects, and evidence stay connected.
- The app becomes more useful as more sources are connected.
- Cursor can continue building features without breaking the core philosophy.
- The architecture supports personal, work, family, finance, and construction use cases without becoming fragmented.

## 7. Five-Year Vision

In five years, Recall should feel like a trusted second brain and personal operations hub.

It should answer questions such as:

- What do I need to do today?
- What am I waiting on?
- Who asked me for what?
- What did I promise to follow up on?
- What has changed since yesterday?
- How much have I spent on the house?
- What documents are related to this issue?
- Which tickets are connected to this person?
- What evidence supports this answer?
- What should I focus on next?

The best version of Recall does not simply store information. It helps the user think clearly.
