Instructions for the reviewing AI

Treat this as a current-state capability audit, not a roadmap or marketing document. Preserve the status labels. Do not assume configuration-dependent integrations are enabled in every deployment. Do not infer missing capabilities from the product vision.

Status legend

  • IMPLEMENTED Working code and a usable product path exist.
  • CONFIG-DEPENDENT Implemented, but requires credentials, external access, or synced data.
  • PARTIAL Some behavior exists, but UI, coverage, persistence, or workflow completeness is limited.
  • NOT IMPLEMENTED Explicitly absent or only represented by a static/decorative UI.

Executive summary

Recall is a single-user-oriented AI personal operating system that captures and syncs information from notes, tasks, files, mail, calendars, contacts, finance, ticket email, and smart-home sources. It converts raw inputs into structured records, connects related entities, provides evidence-backed natural-language answers, and ranks actionable items on Today.

Capture / Connect → Preserve source → Normalize → Extract structure → Human review → Link entities → Retrieve / Ask → Show evidence → Act

The strongest implemented areas are evidence-backed Ask, capture and AI Inbox, notes and attachment extraction, Life Memory, people/waiting-on, project source links, finance summaries, deadline attention, and modular connectors. The largest current product gaps are the static Canvas page, incomplete task/project controls in the visible UI, filename-only quick-capture attachments, text-centric document storage, connector removal UX, and deployment-dependent integrations.

1. Product model and architecture

IMPLEMENTED Recall uses a React/Vite/TypeScript frontend, Express TypeScript API, PostgreSQL with Drizzle, OpenAI integrations, durable database jobs, and modular connectors. Production is hosted behind nginx with PM2 on DigitalOcean.

Core architectural capabilities

  • Shared data model across captures, notes, tasks, people, projects, memories, knowledge, documents, assets, connectors, and evidence.
  • Raw external source records are preserved and deduplicated using connector/external identity.
  • Entity links create typed relationships such as project-to-mail, project-to-transaction, attention-to-source, attention-to-person, person-to-organization, and receipt-to-transaction.
  • Evidence records connect claims and derived items back to source records, excerpts, URLs, and metadata.
  • Durable jobs support capture extraction, attachment extraction, Evernote import, digest regeneration, and deadline scanning.
  • Hybrid retrieval combines full-text/keyword search, semantic embeddings, structured intent handlers, and live connector search.
  • External systems generally remain source of truth; Recall stores searchable normalized snapshots and provenance.

2. Home and Ask

IMPLEMENTED Conversational Home

  • Central natural-language question input.
  • Microphone dictation where browser speech recognition is available.
  • Answer read-aloud using supported speech synthesis.
  • Past-question history and handoff to the full Ask view.
  • Contextual suggestion prompts derived from current Recall data.
  • Related source images when answers are grounded in image evidence.

IMPLEMENTED Evidence-backed Ask

  • Streaming AI answers with deterministic fallback behavior when AI is unavailable.
  • Threaded conversations and follow-up context.
  • Search across notes, attachments, Life Memory, Knowledge, people, tasks, projects, documents, captures, and synced source records.
  • Specialized intent handling for Gmail, Drive, finance, notes, waiting-on, people, and Homey.
  • Confidence, caveats, related records, source metadata, evidence excerpts, and privacy details.
  • Durable Ask threads preserve the evidence snapshot used for each answer.
  • Thumbs-up/down answer feedback.
  • Per-user Ask rules injected as standing instructions.
  • Optional speech playback and answer images.

CONFIG-DEPENDENT Live external search

  • Live Gmail query across connected Google accounts for mail-oriented questions.
  • Live Drive search using Google’s full-text index, including content indexed by Google OCR.
  • Finance and Homey questions require connected/synced data or a live integration.
  • OpenAI synthesis, embeddings, vision OCR, and OpenAI TTS require configured AI credentials.

3. Today and proactive attention

IMPLEMENTED Ranked action queue

  • Combines recommended focus, urgent tasks, AI Inbox reminders, waiting-on items, Homey alerts, and attention deadlines.
  • Deduplicates overlapping recommendations.
  • Links each queue entry to the underlying entity or source context.
  • Allows waiting-on dismissal and follow-up task creation.
  • Allows deadline Seen, Dismiss, and one-day-before Snooze actions.
  • Supports quick brain-dump capture into note, task, or AI Inbox flows.

IMPLEMENTED Briefing and digest

  • Daily briefing, focus recommendation, “don’t forget” list, and Homey urgency integration.
  • Weekly digest with structured sections and local dismissal state.
  • Finance snapshot and waiting-on context can contribute to Home/Today.

4. Capture and AI Inbox

IMPLEMENTED Capture channels

  • Manual typed capture and dictated capture.
  • Today/Home brain dump.
  • Browser extension page/selection capture.
  • Connector ingestion, document import, attachment upload, Evernote import, and Life Memory import.
  • Offline client queue with retry for manual capture submission.
  • Raw capture is retained for provenance.

IMPLEMENTED AI extraction and review

  • Versioned classification into note, task, reminder, work note, project item, or reference.
  • Suggested cleaned title, priority, absolute due date, project, tags, actions, requester, confidence, and evidence quote.
  • Human edit/correction before acceptance.
  • Accept into notes, tasks, or Life Memory; dismiss irrelevant suggestions.
  • Person correction/resolution and source evidence preservation.
  • Durable processing status, retry, and failure visibility.
PARTIAL Quick Capture file selection currently appends filenames to capture/note text; it does not upload those selected files.

7. Life Memory

IMPLEMENTED Life Memory stores durable personal facts that should rank above transient notes.

  • Create categorized facts across family, home, vehicles, health, work, finance, preferences, and other domains.
  • AI-assisted classification and conservative extraction.
  • Search, filter, pin, edit, archive, and inspect history.
  • Corrections preserve history using version supersession rather than destructive overwrite.
  • Effective and expiry dates for time-bound facts.
  • Evidence/source metadata attached to memories.
  • Import review flow before records become active.
  • Markdown “Life File” export.
  • Active/pinned memories are prioritized in Ask retrieval.

13. Finance intelligence

CONFIG-DEPENDENT Requires a configured finance API connector and successful sync.

  • Normalized transaction ingestion with stable external IDs and source provenance.
  • Deterministic spending, income, and net calculations.
  • Date-range, category, payee/merchant, account, project, vehicle, and home analysis.
  • Transaction breakdowns behind reported totals.
  • Classification of expense, income, transfer, credit-card payment, and refund.
  • Transfer and credit-card-payment exclusion from spending totals to avoid double counting.
  • Payee/category summaries and finance snapshot.
  • Likely-subscription detection from recurring transactions.
  • Receipt matching and confirmable transaction links.
  • Project/asset spending suggestions and confirmed typed links.
  • Ask finance intents use records and deterministic aggregation rather than model arithmetic.

NOT IMPLEMENTED Recall is not the authoritative ledger and is not a high-stakes financial advisor. Budget editing and financial write-back are not core current behavior.

15. Deadline Attention System

IMPLEMENTED

  • Durable attention records with title, summary, due date, kind, status, source, evidence, person/project links, confidence, and metadata.
  • Status lifecycle: Open, Seen, Snoozed, Dismissed, Completed.
  • Google Calendar future events promoted without an LLM when start metadata exists.
  • Gmail dated-commitment extraction using a versioned structured prompt.
  • High-confidence auto-create threshold; explicit dated commitments only.
  • Source/person entity links and source evidence.
  • Deduplication by user, source entity, source ID, and due date.
  • Today ranking: overdue, due soon, snooze-expired, then new unseen.
  • API actions for Seen, Dismiss, Snooze presets/custom date, and Complete.
  • Automatic attention scan job after Google sync and a manual API scan endpoint.

PARTIAL Today exposes Seen, Dismiss, and one-day-before Snooze, not every API action/preset. No visible manual “scan now” control was found.

NOT IMPLEMENTED Outbound email, SMS, and push reminder delivery.

18. Browser extension

IMPLEMENTED Chrome/Edge Manifest V3 extension.

  • Capture selected text or current-page visible text.
  • Capture URL, title, hostname, timestamp, and contextual metadata.
  • Specialized Outlook and Teams page-context collection.
  • Preview/edit before sending.
  • Capture-only revocable token; cannot access notes, Ask, finance, connectors, or settings.
  • Token stored client-side while only its SHA-256 hash is stored by Recall.
  • Offline/failure queue with retry during later popup use.

NOT IMPLEMENTED A continuously running service worker that flushes queued captures without opening the popup.

20. Data, evidence, and AI behavior

Evidence model

  • Evidence can identify entity, claim type, source record, excerpt, URL, row/page metadata, and additional metadata.
  • Connector sync updates current evidence rather than appending duplicates indefinitely.
  • Legacy duplicate evidence is collapsed for display.
  • Ask stores exact excerpts and source metadata used at answer time.
  • Financial totals expose their period and underlying transaction rows.

AI behavior

  • Versioned prompts for important structured extraction.
  • Structured JSON validation and deterministic fallbacks.
  • Confidence/caveat handling.
  • Conservative person, project, due-date, and deadline extraction.
  • AI is used for synthesis, semantic matching, classification, summarization, and OCR—not deterministic finance arithmetic.
  • User corrections are preserved and may guide later behavior.
  • Ask rules provide user-defined standing instructions.

Core entity families

Users, sessions, notebooks, notes, note attachments, captures, capture items, tasks, people, projects, organizations, invoices, vehicles, homes, warranties, Life Memory, Knowledge, documents, connectors, sync runs, source records, evidence, entity links, entity embeddings, Ask threads/messages, jobs, waiting dismissals, user rules, corrections, attention items, and audit/activity records.

22. Representative end-to-end workflows

A. Capture a work request

Dictate/paste → Raw capture → AI classification → Review person/date/priority → Accept task → Today/People surface follow-up → Evidence returns to source

B. Lawyer email with court date

Google sync → Gmail source record → Structured deadline extraction → Confidence gate → Attention item + person/source links → Today → Seen/Snooze/Dismiss → Ask cites email

C. Find a fact in a scanned document

Attach image/PDF → Durable extraction/OCR → Indexed text → Ask/Notes search → Answer + evidence excerpt/source

D. Analyze project spending

Finance sync → Normalize/classify → Suggest/confirm project links → Deterministic aggregation → Ask answer → Inspect transactions

E. Track something owed by another person

Task/note/capture/Gmail → Waiting-on heuristic → People/Today → Dismiss or create follow-up task

F. Home emergency alert

Homey Flow → Authenticated Recall webhook → Alert severity → Today/Urgency queue → Acknowledge → Source/device context

G. Teach Recall a permanent fact

Create/import capture → Life Memory review → Categorize/pin/evidence → Ask priority → Correct via versioned supersession → Export Life File

24. Suggested questions for the reviewing AI

  1. Which implemented workflows create the most user value, and which are difficult to discover?
  2. Where do the current UI limitations prevent the backend capabilities from being useful?
  3. Which capabilities overlap or create competing mental models?
  4. Does Today rank the right categories, and how should Seen/Snooze/Complete differ?
  5. Is the evidence model sufficient for high-trust personal, legal, and financial questions?
  6. Which connector behaviors should remain read-only, and where is write-back justified?
  7. What privacy, security, prompt-injection, or data-retention risks deserve priority?
  8. How should Recall communicate sync freshness, extraction confidence, and missing data?
  9. Which partial features should be completed, removed, or hidden?
  10. What is the clearest product information architecture for Home, Today, Ask, Memory, Notes, and Knowledge?
  11. What test/evaluation suite should measure answer grounding, deadline precision, finance correctness, and waiting-on quality?
  12. What three milestones would most improve reliability and daily usefulness?

Final scope statement

This packet aims to enumerate all material implemented capabilities and all material known limitations in the audited repository as of July 18, 2026. It is more exhaustive and technically explicit than the separate user-facing app guide. It intentionally does not list every database column, every API parameter, or every decorative UI element.

Prepared from repository documentation plus direct audit of routed frontend pages, API route families, services, connectors, jobs, security implementation, and browser-extension code. No secrets or credentials are included.
